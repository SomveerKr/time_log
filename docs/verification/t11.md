# T11 release security and resource review

Date: 16 October 2026. Scope: all production Kotlin, build configuration, merged release manifest and resolved runtime dependencies. Local release only; no publication or phone data migration.

## Static security review

- No Internet or broad storage permission, analytics/network SDK, user-history logging, WebView, dynamic code loader, embedded credential or destructive database migration found.
- Launcher activity is necessarily exported; its event extra is length-limited and parsed, and reminder targets are checked against stored state. Receivers use explicit immutable PendingIntents and are not exported. The library profile-install receiver is exported behind the platform DUMP permission. Startup provider and Room service are private.
- Database/files are app-private. OS backup and transfer exclusions remain set. SQL uses bound Room queries, foreign keys, unique indexes and serialized transactions. Restore validates before a transactional replacement, requires user confirmation and leaves reminders off. Cancel/failure paths preserve existing data.
- Backup JSON is intentionally plaintext, with an explanation in the UI. Input is bounded to 20 MiB/100,000 entries with strict fields/types/IDs/references/time/overlap checks. No external-file access beyond user-selected document-provider streams. Streams close using use; file work is on Dispatchers.IO.
- OSV querybatch checked 106 resolved release Maven coordinates; zero matches and no pagination. Evidence: .toolchain/t11-dependencies.json and t11-osv.json. This is a known-advisory database lookup, not an independent penetration test or proof of absence of vulnerabilities.

## Memory, work and storage review

- One application-scoped Room instance; its context is applicationContext. Application-owned reminder/backup helpers also receive Application, not Activity. No static Activity/View reference found.
- ViewModel work uses viewModelScope; reload cancels the previous load job and collectLatest cancels the previous range subscription. Only the selected week plus a two-hour lookback is loaded for ordinary screens, not all historical entries.
- UI clock receiver unregisters on lifecycle stop and composition disposal; no app timer/polling loop or continuously running service. The application database-change collector suspends awaiting changes. Reminders use next-occurrence alarms; the delivery wake lock is limited to 10 seconds and released in finally.
- Lazy lists render history/insights; chart aggregation is remembered by inputs. Fixed one concrete allocation cost: day boundaries now compute once per history-filter call instead of twice per record. No new runtime dependency.
- Release uses R8 optimization/obfuscation and resource shrinking with Android's standard optimized rules. Debugging is explicitly disabled. Normal 60/120-minute schedule unchanged.
- Backup export takes a consistent in-memory snapshot; restore preview retains a validated snapshot until cancel/confirm. These deliberate operations scale with history and can temporarily increase RAM. The 20 MiB input bound is not a 20 MiB heap bound. Very large category sets also increase UI work. No claim of constant memory or zero leaks on every device.
- App storage is the database, SQLite journal and small preferences/runtime caches. Export creates a file only when requested; the user controls its destination and retention. No automatic history deletion, permanent app log or media cache.

## Signing and artifact

Build, signature and 16-KiB alignment verification passed. Release version 1.0.0/code 2. Dedicated RSA-3072/SHA256withRSA key, 10,000-day validity. Key and signing.properties are ignored and ACL-restricted to the current Windows account and SYSTEM. No key/password in source or APK. The release signer differs from the debug signer; do not uninstall the user's debug app or overwrite its data as part of this task.

## Runtime checks and measurements

Passed: optimized signed build, 23 shared-source unit tests, release lint (zero errors/two UseKtx suggestions), 51 API 37 emulator tests, v2 signature and 16-KiB alignment checks. The installed APK is not debuggable and run-as was refused before emulator root was enabled for storage measurements. The exact release opened setup, saved a synthetic one-hour Work entry, displayed the correct daily chart, and exported 1 entry/8 categories through the native picker. Initial PSS was 28,802 KiB, with one Activity; validated 10,000-entry preview PSS was 29,055 KiB. Large restore, restart, native export and field-by-field comparison passed for all 10,000 entries and the category. All portable settings match except the reminder switch explicitly enabled for notification testing. The first interrupted restore retained the prior entry; the completed retry is the accepted run. API 37 emulator has 2 GiB configured RAM. No phone is connected in this session. Earlier phone evidence remains in t10.md and is not counted as new release evidence.

### Actual release resource exercise

API 37 x86_64 emulator, 2 GiB RAM; synthetic 10,000 one-minute entries with short notes. Airplane mode enabled and Wi-Fi disabled during reporting, test notification/deep link, scheduling and large export. Release source/timing was not altered. Normal next-occurrence alarm was registered at 11:00 with inexact fallback. No new long scheduled-delivery observation is claimed.

All 30 cycles used the same process, recreating the task with `am start -W -f 0x10008000` and navigating Insights/Settings/back. The initial helper used an unsupported flag and is excluded; the corrected helper checks recreation failures. Memory fluctuated and returned toward baseline; Activity count did not accumulate. No app crash-buffer records or running service were reported. This is a bounded leak screen, not a heap-dominator analysis or a guarantee for every device/workload. PSS apportions shared pages; RSS is larger and is not equivalent to exclusive app RAM.

Private app storage was 3,352 KiB including database/journal/cache for 10,000 records, unchanged after the 30 cycles. The exported synthetic JSON was about 2.34 MiB in user-selected Downloads, separate from private storage. Storage grows with saved history and user-created backup files by design.

Visual inspection: actual release setup, category entry/Save, daily Insights, large weekly Insights, restore preview and dark Today screenshots were reviewed. Native backup export/restore, cold restart persistence, notification permission, offline test notification/tap and future normal schedule registration passed. No test draft was saved during the notification check. Temporary emulator root, airplane mode/Wi-Fi and night-mode changes were restored; no physical phone was changed.

No signing secrets, personal data or generated artifacts are committed. APK ZIP inspection found no keystore, signing properties, database, heap dump or test artifacts.

Limits: no physical-phone release profiling, minimum-API release runtime test, exhaustive penetration test or long-term leak/overnight run. T10's long reminder/snooze/post-reboot limits still apply. Back up both signing files securely; debug-to-release migration requires an exported user backup before manual uninstall because certificates differ.

## Internet verification

The signed APK was checked with aapt dump permissions: no INTERNET permission, no ACCESS_NETWORK_STATE permission and no broad storage access. Production source has no network client, telemetry, analytics or cloud-sync code. Core features do not access the Internet. A user-selected cloud document provider is a separate app and may upload/download the selected backup; choose local Downloads/Documents for local-only backup. OS cloud-backup/transfer exclusions are also configured. This conclusion applies to the verified APK hash below, not arbitrary future builds.

APK SHA256: `4964E16F003031E7A11A15325712284B0F2E5AACF4279CB62E7168EFE2BF708C`. Size: 1,529,279 bytes (1.46 MiB), about 87% below the prior 12,020,368-byte debug artifact.
